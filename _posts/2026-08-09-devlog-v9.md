# oh my gog, rebuilding my gogs git server after a meltdown

sat down tonight ready to do some homelab work. was hyped to tackle either a new project, an old project,
 my two clusters, mcu development or just general tinkering

sadly, i did not get very far.

## the gitserver

i run gogs on a tiny dell vostro a100 (the rare x64 variant).
2gb ram, 500gb hdd, pico psu.
perfect for a lightweight git server that just sits there and does its job.

## gogs

- sqlite backend
- `/opt/gogs` for the binary
- `/opt/gogs-repos` for repos
- systemd service
- no frameworks, no daemons, no nonsense

gogs is fast, tiny & predictable, until it decides not to be

## the breakage

at some point the install went very strange;

- ui showed “initialize repository”, even with new repos and after a fresh sucessful push
- repo existed, it was there
- objects existed, i checked.
- head existed, i checked.
- refs existed, i checked those too
- pushes succeeded, no issue with getting the physical files onto the server
- https worked
- ssh didn’t
- db entries were correct
- filesystem was correct


the worst kind of failure; when everything underneath is fine, but the surface lies

## the reset

eventually i stopped trying to repair it and just did the clean, correct thing

reinstall!

luckily, just before this happened i synced all my important repos,
 so it was completely safe to wipe everything in `opt`

steps:

1. stop service
2. remove `/opt/gogs-repos` 
2. remove `/opt/gogs`
4. extract fresh copy
5. run installer cleanly
6. set run user to `sysadmin`
7. restore repos
8. restart service

everything came back instantly.

## the aftermath

all my repos are back, homelab is stable again and i have a clean slate to work from.
